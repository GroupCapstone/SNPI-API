## 1. Original Topic Definition

> "Indicates that the resource requested is no longer available and will not be available again. This should be used when a resource has been intentionally removed and the resource should be purged. Upon receiving a 410 status code, the client should not request the resource in the future. Clients such as search engines should remove the resource from their indices. Most use cases do not require clients and search engines to purge the resource, and a *404 Not Found* may be used instead.
"

## 2. Architectural Principles Learned

This design topic governs **410 Gone** within the domain of **HTTP Status User Error**.

### Key Considerations for Modern REST APIs:
* **Consistency & Predictability**: APIs must treat `http-status-410` predictably across all endpoints, minimizing consumer surprise.
* **Client Decoupling**: Contracts regarding `http-status-410` must decouple client implementation details from internal service models.
* **Scalability & Performance**: Proper design of `http-status-410` prevents unneeded compute overhead, database contention, and network payloads.
