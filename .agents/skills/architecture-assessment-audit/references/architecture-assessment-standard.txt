1. CORE ARCHITECTURAL PRINCIPLES (10 DOMAINS)
--------------------------------------------------------------------------------
1. Scalability by Design:
   System throughput and storage scale horizontally with predictable cost models.
   Compute non-ephemeral resources maintain >= 30% headroom for peak traffic.

2. Resiliency & Fault Isolation:
   Failures are isolated; services degrade gracefully with zero cascading outages.
   Automated backups, encrypted storage, and high availability (HA) across AZs.

3. Efficiency without Premature Optimization:
   Resources protected against waste; APM profiling isolates bottlenecks.
   Automated build, test, and deploy pipelines eliminate human toil.

4. Radical Simplicity:
   System topology kept straightforward; modular monolith preferred over microservices
   sprawl until domain scaling strictly necessitates it.

5. Continuous Verifiable Documentation:
   Architecture specs and operational runbooks maintained in real-time sync with code.

6. Zero-Loss Disaster Recovery:
   RPO < 15 min, RTO < 60 min. Automated cross-region replication and git reflog
   force-push recovery verified via regular staging drills.

7. High Cohesion & Loose Coupling:
   Module boundaries enforced strictly via strongly typed shared DTO contracts.

8. Open Standards & Interoperability:
   Standardized REST/OpenAPI interfaces, semantic versioning, and open-source license
   obligations strictly fulfilled.

9. Omnipresent Observability:
   Structured JSON logging, sensitive data redaction, real-time metrics dashboards,
   and calibrated actionable alerting with anomaly detection.

10. Zero-Trust Enterprise Governance:
    SAML SSO, RBAC access audits, secret scanning, push protection, and on-premises
    GHES network isolation and ghe-backup utilities.

3. PRIORITY MATRIX & SLA ENFORCEMENT
--------------------------------------------------------------------------------
[P0] Critical / Blocker:
   - Data loss risk, zero backup verification, unhandled force push, broken SSO/RBAC,
     single point of failure.
   - SLA: Immediate.
   - CI/CD Action: Fails build immediately; deployment strictly prohibited.

[P1] High:
   - HA failover absence, unmonitored replication, missing branch protection, config drift.
   - SLA: 7 calendar days.
   - CI/CD Action: Warning in CI; blocks production release tag.

[P2] Medium:
   - Missing APM profiler, suboptimal cache TTLs, absence of service discovery.
   - SLA: 30 calendar days.
   - CI/CD Action: Tracked in architecture debt backlog.

[P3] Low:
   - Naming convention minor variations, documentation styling, non-critical logging.
   - SLA: Scheduled sprint.
   - CI/CD Action: Continuous improvement recommendation.
