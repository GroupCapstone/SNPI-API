DEFENDING AGAINST DEPENDENCY SUPPLY CHAIN ATTACKS
Authors: Ken Muse and Josh Johanning
Published: December 10, 2025 | Updated: October 2, 2026
Source: GitHub Well-Architected Framework & Application Security Recommendations

1. SCENARIO OVERVIEW
Modern software development relies heavily on dependencies - third-party packages, libraries,
and modules that accelerate development but also introduce security risks. Supply chain attacks
targeting dependencies have become increasingly sophisticated (typosquatting, package confusion,
package hijacking, account takeovers, malicious code injection into legitimate packages).
Example: Shai-Hulud self-replicating worm infiltrating npm ecosystem via compromised maintainer
accounts, injecting malicious post-install scripts that stole credentials, backdoored packages,
and wiped user home directories. Managing dependency threats requires layered defense-in-depth.

2. CORE 6-LAYER DEFENSE-IN-DEPTH STRATEGY
Layer 1: Disable Package Lifecycle Scripts by Default
- Package lifecycle scripts (preinstall, install, postinstall) execute with full user privileges.
- Configure .npmrc: ignore-scripts=true, save-exact=true.
- In CI workflows: npm ci --ignore-scripts.
- Whitelisted native modules: run selective npm rebuild <package-name>.

Layer 2: Use Dev Containers for Isolation
- Isolates host files, SSH keys, cloud credentials, and sensitive directories from execution runtimes.
- Run containers as non-root user (e.g., vscode or node) with restricted sudo privileges.
- GitHub Codespaces scopes git credentials to defined repositories.

Layer 3: Require Signed Commits with User Interaction
- Cryptographic commit signing using GPG, SSH, or S/MIME keys.
- Requires human-in-the-loop interaction (passphrase, biometric Touch ID, or hardware YubiKey).
- Blocks automated malicious scripts from forging commits on the developer's behalf.

Layer 4: Enforce Repository Rulesets
- Default branch protected with non-bypassable rulesets.
- Require PRs, required status checks, 2 approvers, re-review on push, code scanning gates.

Layer 5: Establish Trusted Publishing & Verification
- Eliminate long-lived tokens via OIDC trusted publishing (SLSA Build Level 3).
- Publish with cryptographic provenance attestations: npm publish --provenance.
- Verify package attestations using npm audit signatures in CI/CD pipelines.

Layer 6: Monitor & Respond Continuously
- Dependabot alerts with auto-triage rules and scheduled update groups.
- Dependency review action (actions/dependency-review-action) blocking high/critical findings.
- Code scanning (CodeQL) and secret scanning with push protection.
- Human review of dependency diffs; never rely solely on SemVer for security.

3. IMPLEMENTATION INVARIANTS & VERIFICATION
- INVARIANT-1: .npmrc exists at repository root with ignore-scripts=true and save-exact=true.
- INVARIANT-2: .devcontainer/devcontainer.json exists with non-root user configuration.
- INVARIANT-3: Commit signing policy enforced in repository rulesets and AGENTS.md.
- INVARIANT-4: Branch protection / ruleset requires pull requests and status checks.
- INVARIANT-5: CI workflows execute dependency installs with lifecycle scripts disabled.
- INVARIANT-6: Dependency review action active on pull requests targeting default branch.
